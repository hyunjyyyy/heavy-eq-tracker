## 몰랐던 것 → 알게 된 것
- MySQL 9.7 `EXPLAIN` 기본 출력이 트리 → 안쪽부터 실행. `Sort:` 노드 = `Using filesort`, `(reverse)` = `Backward index scan`. 옛 표 형식은 `FORMAT=TRADITIONAL`
- `LIMIT 1`인데 25,047행을 읽는 이유 → 장비 인덱스로 찾은 뒤 시각 정렬을 따로 해야 해서. `(equipment_id, recorded_at)`이면 구간 끝에서 1행
- 복합 인덱스 열 순서 → 왼쪽 열부터(leftmost prefix). 등호 열 → 범위·정렬 열. 반대 순서면 왼쪽에 등호 조건이 없어 못 탄다. 인덱스 하나가 캐시 미스·이력 두 쿼리를 덮음
- FK가 만든 단일 인덱스는 복합 인덱스 생성 시 **InnoDB가 자동 제거** → `SHOW INDEX`에서 사라져 있었음
- 추정 rows(49,304)가 실측(25,047)의 2배, `ANALYZE TABLE` 뒤에도 그대로 → 계획엔 영향 없음. 추정과 실측은 `EXPLAIN ANALYZE`로 같이 본다
- N+1의 N은 행 수가 아니라 **서로 다른 부모 수** → 1차 캐시. 이력 50행(장비 1대)은 1+1, 최근 50행(장비 3대)은 1+3. 예측 1+4가 1+3인 건 장비 4가 최근 50건에 없어서
- `open-in-view=true`면 N+1이 어디서 생기나 → Jackson 직렬화 중, 내 코드에 getter 호출 줄이 없고 응답 끝까지 커넥션을 붙잡는다. false라 Service의 DTO 변환 줄에서 즉시 보인다
- `@EntityGraph` 후 SQL은 `join equipment`(inner) → `@JoinColumn(nullable = false)` 덕. nullable이면 left join
- 현황 API의 장비 목록은 GEO `fleet`의 member → `ZRANGE` + `MGET`. 생성 데이터 10만 건은 앱을 안 거쳐 Redis에 없다
- Spring 7은 Controller 파라미터의 `@Size`·`@NotBlank`를 `@Validated` 없이 검사한다 → 헤더 길이 위반이 ArgumentResolver 단계에서 400
- 탐색 반경을 고정값으로 두면 오차 합이 반경을 넘을 수 있다 → 반경은 임계 + 오차 상한×2로 **유도**해야 모순이 없다(내 설계 실수를 검수가 잡음)
- GEO member에는 TTL이 없다 → `loc:` 신선도로 거르면 GEO 정리 없이도 유령 장비를 뺄 수 있다
- 검수 항목 중 "인덱스 없음"은 그 뒤 PR로 해결됐었다 → 검수 결과는 **어느 커밋 기준인지**부터 본다
- `@EventListener`는 동기 → 발행한 스레드·트랜잭션 안에서 바로 실행된다. 리스너 예외가 writer까지 올라와 이벤트 INSERT도 같이 롤백 → 직접 호출과 결과가 같다
- `@TransactionalEventListener(AFTER_COMMIT)`는 커밋 뒤에 실행 → 판정(롤백 같이)은 `@EventListener`, 캐시·GEO(롤백 불가)는 `LocationRecorded`의 AFTER_COMMIT. 이벤트 두 개를 나눈 이유
- 패키지 순환 끊기 → 아는 쪽(`location`)이 이벤트만 발행하고 듣는 쪽이 의존. 양쪽을 다 쓰는 것(현황)은 별도 패키지로 뺀다
- 리스너 여러 개의 실행 순서는 정해져 있지 않다 → 서로 결과를 쓰게 되면 `@Order`
