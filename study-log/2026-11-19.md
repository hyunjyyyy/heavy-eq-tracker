# 2026-11-19

## 한 것
- 자바 고위험 취약점(Java4Shell, CVE-2026-114938) 보도를 보고 이 프로젝트가 영향받는지 점검. JDK는 영향 버전(Temurin 21.0.13 < 21.0.13.1)이지만 실제 위험은 없다 — 개발 PC CPU에 AVX-512가 없고, 코드에서 `Base64`를 쓰지 않는다. Kafka 컨테이너의 JDK도 같은 CPU·localhost라 해당 없음.

## 몰랐던 것 → 알게 된 것
- Java4Shell이 뭔가 → OpenJDK `Base64.getDecoder()`·`getUrlDecoder()`의 AVX-512 최적화 코드(intrinsic)가 잘못된 입력에서 힙 밖에 쓰는 결함. `getMimeDecoder()`는 이 경로를 안 탄다.
- 버전만 맞으면 위험한가 → 아니다. 영향 버전 + x86-64 AVX-512 VBMI CPU + 외부 입력이 그 디코더로 들어가는 경로, 셋이 다 있어야 한다. ARM64는 해당 없음.
- 고친 버전 → 17.0.21.1 / 21.0.13.1 / 25.0.5.1 / 27.0.1.1. Java 8·11은 영향 없음.
- 바로 패치 못 할 때 → `-XX:-UseBASE64Intrinsics`(그 경로만 끔) 또는 `-XX:UseAVX=2`. 적용 여부는 셸의 `java -version`이 아니라 `jcmd <PID> VM.flags -all`로 실행 중인 프로세스에서 확인.
- 개발 PC가 안전해도 서버는 다를 수 있다 → 클라우드 서버 CPU(Xeon, AMD Zen 4 이상)는 AVX-512가 있는 경우가 많다.
