## 몰랐던 것 → 알게 된 것
- 고정 윈도우 "경계 문제" → 에러가 아니라 창 경계에서 한도의 2배가 통과하는 것. 고장 단말 차단이 목적이면 무해, 과금·쿼터면 문제
- `INCR` 뒤 `EXPIRE` 전에 죽으면 → 다음 초는 다른 키라 통과. 죽은 초의 키만 TTL 없이 영원히 남음 → Lua로 한 명령
- 속도 제한 키를 IP가 아니라 장비 ID로, 그것도 헤더로 받는 이유 → 목적(자원 보호)상 Filter에서 잘라야 하고 Filter는 바디를 못 읽는다. NAT 뒤 장비 여러 대가 한 IP
- Filter에서 거부할 땐 `@ControllerAdvice`가 안 닿아 429 JSON을 직접 써야 한다
- `curl.exe` 15번이 전부 201 → 프로세스 생성이 느려 1초를 넘긴 것. `Invoke-WebRequest` 30번은 201×10 + 429×20. 측정 도구가 결과를 바꾼다
- 캐시 미스 경로 쿼리(`where equipment_id=? order by recorded_at desc limit 1`)에 인덱스가 없다 → Day 5 EXPLAIN 대상. 없는 장비 조회는 매번 DB(부정 캐시 없음)
- Kafka가 큐가 아니라 로그인 이유 → 읽어도 안 지우고 오프셋만 움직인다. 그래서 나중에 붙은 소비자도 과거를 읽고, 재시작해도 이어 읽고, 되돌려 재처리할 수 있다
- "프로듀서와 브로커"가 뭔지 → 프로듀서는 내 Spring 서버의 `kafkaTemplate.send`, 브로커는 Kafka 컨테이너. 멱등 프로듀서는 그 사이 네트워크 재전송 중복만 거른다
- 파티션 수를 늘리면 왜 순서가 깨지나 → `hash % N`이 바뀌어 같은 장비의 새 메시지가 다른 파티션으로 가고, 옛 파티션에 남은 것과 처리 순서가 어긋난다
- 새 컨슈머 그룹이 과거 메시지를 못 받는 이유 → 커밋 오프셋이 없으면 `auto.offset.reset`, 기본 `latest`
- Boot 4에서 `spring-kafka`만 넣으면 `KafkaTemplate` 빈이 없다 → 자동 구성이 `spring-boot-kafka` 모듈로 분리됨. **스타터**(`spring-boot-starter-kafka`)를 넣어야 한다. Flyway의 `starter-flyway` + `flyway-mysql`(DB 모듈)과 같은 구조
- `Record in retry and not yet recovered` 반복 → 콘솔로 넣은 비JSON 메시지를 `earliest`로 읽다 파싱 실패 → 기본 핸들러가 10회 재시도 후 건너뜀. 재시도해도 소용없는 예외(poison pill)는 DLT로 보내야 한다는 것
- 선점 키가 Redis에 남아 있으면 202를 주지만 발행이 안 된다 → 첫 실험에서 60건이 토픽에 0건. `ProducerConfig values` 로그가 첫 send 때 찍히는 걸로 발견
- `Invoke-WebRequest`는 4xx에 예외를 던져 루프를 끊는다 → 장비 id 2가 없어 40건에서 멈춤. 실험 스크립트는 4xx를 삼켜야 한다
- PowerShell 함수·변수는 탭마다 다시 정의해야 한다 (`mysqlq`)
- 컨슈머 재합류 때 파티션 배정이 매번 같지 않다 (8080이 2개 → 8081이 2개)
- `kafka-consumer-groups --reset-offsets --to-earliest --execute`로 "처리 중 죽어 재소비"를 재현할 수 있다
