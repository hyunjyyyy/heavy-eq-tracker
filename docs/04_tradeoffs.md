# 04_tradeoffs.md

> "무엇을 얻기 위해 무엇을 포기했는가?"

## Day 1

### 1. MySQL 9.7 (vs PostgreSQL)
* **얻은 것**: 공고 요건 충족. InnoDB 클러스터드 인덱스, EXPLAIN 표 형식, REPEATABLE READ 기본값, DDL 비트랜잭션이라는 **다른 점**을 직접 겪는다.
* **포기한 것**: DDL 롤백(Flyway 실패 시 복구가 더 번거롭다), PostGIS 수준의 공간 연산, 이미 손에 익은 운영 감각.
* **바뀌는 조건**: 없다. 이 프로젝트의 존재 이유와 묶여 있다.

### 2. `BIGINT AUTO_INCREMENT` (vs UUID)
* **얻은 것**: 순차 INSERT로 클러스터드 인덱스가 뒤에만 자란다. 보조 인덱스(`uk_location_event_idempotency`, 이후 복합 인덱스)가 8바이트 PK를 가리켜 작다.
* **포기한 것**: 앱에서 ID를 미리 알 수 없어 배치 INSERT가 안 된다(IDENTITY는 INSERT 즉시 실행). 여러 수집 서버가 각자 ID를 만들어야 하는 구조로 가면 불리.
* **바뀌는 조건**: 3일 차 Kafka 이후 "이벤트 ID를 발행 시점에 알아야 하나"가 생기면 재검토.

### 3. `lat/lon DOUBLE` (vs `POINT`)
* **얻은 것**: 매핑 한 줄, 시험 데이터 만들기 쉬움, 점-다각형 판정을 앱 코드로 설명 가능.
* **포기한 것**: 공간 인덱스. 반경 조회를 DB가 못 하고 앱이 전부 읽어서 거른다.
* **바뀌는 조건**: 4일 차에 "장비 N대 × 구역 M개" 판정이 느려지면 `POINT` 열 추가 + 네이티브 쿼리. 그때가 "JPQL의 경계"를 보여 주는 지점이라 오히려 의도된 전환.

### 4. `@ManyToOne` (vs `Long equipmentId`)
* **얻은 것**: N+1을 **실제로 겪고** fetch join / `@EntityGraph`로 고치는 전후 쿼리 수를 기록할 수 있다. `event.equipment.name` 같은 탐색이 코드에서 자연스럽다.
* **포기한 것**: 이벤트 표의 가벼움. LAZY 프록시, `open-in-view`, `LazyInitializationException`이라는 관리 비용이 따라온다.
* **찝찝한 점**: 설계만 보면 B가 맞다는 걸 알면서 골랐다. 면접에서 "왜 걸었나"에 "공부하려고"라고 답할 수 있어야 한다.

### 5. Flyway 표당 파일 하나 (vs V1 하나)
* **얻은 것**: MySQL에서 실패 지점이 파일 하나로 좁혀진다. 실제로 V2 실패 때 V1은 멀쩡했다.
* **포기한 것**: 파일 수. "초기 스키마 한 덩어리"라는 가독성.
* **바뀌는 조건**: PostgreSQL이었으면 안 쪼갰다.

### 6. `.env` 단일 출처 + Gradle이 시험에 주입 (vs yml 기본값)
* **얻은 것**: 값이 한 곳에만 산다. 설정이 없으면 조용히 기본값으로 돌지 않고 죽는다.
* **포기한 것**: 클론 직후 아무 설정 없이 `gradlew build`가 도는 편의. `build.gradle.kts`에 5줄.
* **바뀌는 조건**: 5일 차 Testcontainers로 가면 시험이 컨테이너가 알려 주는 접속 정보를 쓰므로 이 장치 자체가 필요 없어진다.

### 7. 시험이 로컬 compose MySQL을 공유 (vs 시험 전용 DB)
* **얻은 것**: 오늘 쓸 코드 0줄.
* **포기한 것**: Docker가 떠 있어야 빌드가 통과. `bootRun`은 compose 환경변수로, 시험은 `.env`로 접속하므로 둘이 같아야 한다는 결합. 시험이 남긴 데이터가 다음 `bootRun`에 보인다(오늘 `k-001`이 그 예).
* **바뀌는 조건**: 5일 차.

### 8. 멱등 중복 시 200 + 기존 id (vs 409)
* **얻은 것**: 단말이 재전송을 성공으로 본다. "멱등"의 뜻에 맞는 API.
* **포기한 것**: 요청당 SELECT 1회 추가. 동시 요청 시 둘 다 조회를 통과해 하나가 UNIQUE 위반으로 500이 나는 구멍.
* **바뀌는 조건**: 2일 차 Redis `SET NX`로 선점하면 구멍이 닫힌다. 그때 C로.

### 9. `getReferenceById` 대신 `findById` (오늘은 그대로)
* **얻은 것**: 없는 장비를 INSERT 전에 명확한 예외로 잡아 404로 바꾼다.
* **포기한 것**: 요청당 SELECT 1회(장비 행 전체).
* **바뀌는 조건**: 4일 차 쿼리 수 줄이기. FK 위반을 404로 번역하는 쪽이 낫다고 판단되면 바꾼다.

### 10. 코드를 받은 지점들
* **얻은 것**: 시간. 문법에서 막혀 하루가 끝나는 걸 피했다.
* **포기한 것**: "내가 썼다"고 말할 수 있는 범위. 02의 1.11에 적어 두고, 다음 날 같은 모양을 받지 않고 쓸 수 있는지로 확인한다.
